Data Processing and Analysis

It’s hard for me to be prescriptive here - what’s required of you will depend on the data you choose. In general, it is hard for me to think of a project that wouldn’t benefit from multiple data sources or datasets. Additionally, your project will almost certainly involve “cleaning” the data. To do so, you should deal with missing or incorrect information, create variables where needed, and normalize units where relevant.8 Different projects will have different cleaning requirements. Please have the proper amount of cleaning totally depends on your data. Almost all datasets require some cleaning though.

look-ahead bias: Since this is a prediction task, be mindful that you can only use data available to the date for prediction. For example, the Q1 US GDP growth rate is labeled to be at the end of march, but it is not announced until Thursday, September 25, 2025! If you are predicting April returns, you cannot use this number.

In general, if you are uncertain about the announcement lag (if there is any), you can use this rule for finance/econ data: 1 month lag for monthly data, 4 month lag for quarterly data and 6 month lag for annual data. Therefore,to predict returns at month \(t+1\), you can use most recent monthly data at the end of month \(t-1\), most recent quarterly data by end \(t-4\), and most recent annual data by end \(t-6\).

Note that there are real-time information which do not require lag, such as prices (asset prices or portfolio prices). Therefore, if you are trying to use March return to predict April return, you do not need to lag it!

training, validation and test: For machine learning model estimations in general, we need to divide data into training, validation and test sets. There is no definite rule for the size ratio of the three sets, but For this project, you need to have: 40% training, 20% validation, 40% testing.

  • Training set: We use this set to estimate the model parameters.
  • Validation set: We use this set to select the tuning parameters for machine learning models.
  • Testing set: We use this set to evaluate the model.

For cross-sectional data (no time), we can just randomly split the data into three sets by drawing their index. For time-series, there are a few different approaches. With the example of year 1985 to 2024, I will introduce three approaches here:

  1. Fixed window: 1985-2000 as training, 2001-2008 as validation, and 2009-2024 as testing. This is not recommended if you know the model parameters are changing.

  2. Rolling window: Have a 12-year rolling-window and 1 additional year for testing at a time, then move everything forward by 1 year:

  • 1985-2000 as training, 2001-2008 as validation, and 2009 to evaluate the model
  • 1986-2001 as training, 2002-2009 as validation, and 2010 to evaluate the model …
  • 2000-2015 as training, 2016-2023 as validation, and 2024 to evaluate the model
  • You can show the evaluation performance as a plot over time, or simply average the evaluation metric.
  1. Expanding window: Have a 12-year rolling-window and 1 additional year for testing at a time, then expand training window by 1 year and everything else forward by 1 year:
  • 1985-2000 as training, 2001-2008 as validation, and 2009 to evaluate the model
  • 1985-2001 as training, 2002-2009 as validation, and 2010 to evaluate the model …
  • 1985-2015 as training, 2016-2023 as validation, and 2024 to evaluate the model
  • You can show the evaluation performance as a plot over time, or simply average the evaluation metric.

For this project, I will require the use of expanding window.

Missing data: There are different ways to address missing data. You can use historical mean, the previously observed value, or some other advanced techniques to do it. You can use previously observed value for simplicity.

Mixed frequency: We are trying to predict monthly returns, but variables like GDP growth rate is a quarterly data. There are different ways to deal with mixed frequency too. You can use previously observed value for simplicity.

That means, if we see 1.2% GDP growth rate for March (Q1) and 1.5% GDP growth rate for June (Q2), we can fill in 1.2% for April and May.

Variable Reasoning

If the economy is in good shape, it would provide more business opportunities. People would be willing to invest in stocks and the stock price would be higher, achieving higher returns. Therefore, GDP growth rate might be a useful predictor for stock returns.

There are some momentum reasoning for using past return to predict future return. If the stock market is performing well, more people would buy it and price is pushed higher, achieving higher returns.Therefore, lagged monthly SP500 return might be a useful predictor for stock returns.

Note that returns is a rate, we need to use rate to predict it. Instead of GDP level, I would use GDP growth rate here. It is generally a bad idea to use level to predict rate!

Linear Model Estimation

This section, we will finally estimate the linear model. Remember that we should have an expanding window, split the dataset into training, validation and testing. However, since linear model does not have tuning parameters, we would just put the validation set into training set: - 1985-2008 as training, and 2009 to evaluate the model - 1985-2009 as training, and 2010 to evaluate the model … - 1985-2023 as training, and 2024 to evaluate the model

# Preallocate the fitted data from 2009 to 2024
Testing_result = Total_data |>
  filter(predicting_date >= "2009-01-01") |>
  # Only keep the predicting_date, predicting_return, and create fitted_return
  select(predicting_date, predicting_return) |>
  rename(actual_return= predicting_return) |>
  mutate(fitted_return = NA)


# Use a for loop to estimate each model and lm for linear regression
# Start from the end year 2008 to 2023 which are the end of training periods
for (i in 2008:2023) {
  # Extract the Training data
  Training_data = Total_data |>
    # before i+1 year
    filter(year(predicting_date) < i+1) |>
    # Only keep the predictors and the predicting_return
    select(c(predicting_return, all_of(Variable_names)))
  
  # Estimate the model
  Model = lm(predicting_return ~ ., data = Training_data)
  
  # New data to predict
  Testing_data = Total_data |>
    # at i+1 year
    filter(year(predicting_date) == i+1) |>
    # Only keep the predictors
    select(all_of(Variable_names))

  # Make predictions and save to year i+1 using logical indexing
  # Use predict to estimate the fitted data based on model and test data
  Testing_result[year(Testing_result$predicting_date) == i+1, "fitted_return"] = predict(Model, newdata = Testing_data)
}

Estimate the out of sample \(R^2\) (\(R^2_{OOS}\), based on the testing period). Usually, we assume the return to be 0 average. The R squared for return is defined as:

\[R^2_{OOS} = 1-\frac{\sum(y_{actual} - y_{predict})^2}{\sum y_{actual}^2}\]

The closer it is to 1, the better the prediction accuracy.

# calculate OOS r squared based on the formula
R_sq_oos = 1 - sum((Testing_result$actual_return - Testing_result$fitted_return)^2)/sum((Testing_result$actual_return)^2)
R_sq_oos
## [1] -0.02238912

We get negative out of sample \(R^2\)! If we predict 0, we would get \(R^2_{OOS} = 0\), so the linear model is doing a worse job than just simply guessing 0 return!

We can further explore which years are doing the worst and which years the model is fine. Let’s calculate the \(R^2_{OOS}\) based on every 4 years. (Use 4 years is to have sufficient amount of data to estimate the \(R^2_{OOS}\), while having several periods for comparison.)

# Create a function to estimate R_Sq_oos
R_Sq_oos_func = function(actual_return, fitted_return) {
  return(1 - sum((actual_return - fitted_return)^2)/sum((actual_return)^2))
}

# Estimate every 4-year R_sq_oos
R_sq_oos_table = Testing_result |>
  # first break the dates into 4 year periods
  mutate(
    year = year(predicting_date),
    period_4yr = cut(year, breaks = seq(min(year), max(year) + 3, by = 4), right = FALSE)
  ) |>
  group_by(period_4yr) |>
  summarise(R_Sq_oos = R_Sq_oos_func(actual_return, fitted_return))

A Simple Trading Strategy Based on the Simple Model

The actual meaning of such predictive model is that we can implement trade on it! (You can think of this as a way to evaluate the predictive model. The more money we can make, the better the model is.)

For example, let’s have a strategy that: - We buy/hold the SP500 index if we predict positive returns next month. - We sell/not buy the SP500 index if we predict negative/zero returns next month.

In reality, you can choose a more complicated threshold for buying/selling. Or even allow short selling. For demonstration purpose, we will stick to the simplest one.

To see whether our combination of predictive model and trading strategy is effective, we will compare our linear model + simple strategy’s cumulative return (buyLMpositive) vs. buy and hold cumulative return (buyANDhold):

# Create a dataset for trading strategy comparison: buyLMpositive vs. buyANDhold
Trading_Strategy = Testing_result |>
  # Create a logical index of whether we realize the monthly return based on our trading strategy
  mutate(Trade = (fitted_return > 0)) |>
  # Create a buyLMpositive strategy 
  mutate(buyLMpositive_ret = Trade*actual_return)


# Now, use for loop to calculate the cumulative gross returns
# Preset the two strategy
Trading_Strategy$buyLMpositive = NA
Trading_Strategy$buyLMpositive[1] = 1
Trading_Strategy$buyANDhold = Trading_Strategy$buyLMpositive

# Loop
for(i in 2:nrow(Trading_Strategy)) {
  Trading_Strategy$buyLMpositive[i] = Trading_Strategy$buyLMpositive[i-1] * (1+Trading_Strategy$buyLMpositive_ret[i]/100)
  Trading_Strategy$buyANDhold[i] = Trading_Strategy$buyANDhold[i-1] * (1+Trading_Strategy$actual_return[i]/100)
}

# Plot the cumulative returns
# Only select buyLMpositive and buyANDhold; and make the data longer
Trading_Strategy |>
  pivot_longer(c(buyLMpositive, buyANDhold), names_to = "Strategy", values_to = "CR") |>
  ggplot(aes(predicting_date, CR, color = Strategy)) +
  geom_line(linewidth = 1) +
  theme_minimal() +
  labs(
    title = "Cumulative Returns with Different Trading Strategies",
    x = "Date",
    y = "Cumulative Returns",
    color = "Trading Stategy"
  ) +
  theme(
    legend.position = "top",
    plot.title = element_text(hjust = 0.5)  # <-- Center the title
  )
